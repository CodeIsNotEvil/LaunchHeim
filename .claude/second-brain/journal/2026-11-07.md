# 2026-11-07

- The owner found that "Install with Steam" on the Servers page did nothing, with Steam running.
  `DesktopShell.Open` only passes web links and files, so the `steam://` link was dropped without a
  word. Fixed with `DesktopShell.OpenSteamLink` (only `steam://`, only LaunchHeim's own links) and a
  toast either way. The servers' Start buttons now also notice a server program Steam installed while
  the page was open ([[server-manager]], PR #3).
- After Steam installed the server, LaunchHeim still said "install it through Steam". The cause was
  LaunchHeim's own SteamCMD, which had rewritten the Steam client's library list without
  `/mnt/games/SteamLibrary` ([[launchheim]] Gotchas). SteamCMD now gets a home of its own; the owner's
  `libraryfolders.vdf` needed repairing.
- Starting a server crashed LaunchHeim: the start's progress reporter was created inside `Task.Run`,
  so its reports reached Qml.Net off the UI thread ([[launchheim]] Gotchas). It is now created before
  `Task.Run`, like everywhere else.
- The owner asked for a server's start to be visible without the console, and for a one-click Join with
  a remembered character and the server's own instance. Built:
  - `ServerStartup` reads the stage from the server's log; online now needs that log line or A2S,
    because the plugin answers RCON while the world is still loading.
  - The start card with a progress bar and a toast when it's online.
  - Join stores its choice under Valheim's key `server:127.0.0.1:<port>`, so the sidebar, the CLI and
    the Play page reuse it.
  Checked with a real server in the scratch setup (screenshots of starting, online and the list).
  Joining itself wasn't run, since it would start the game on the owner's desktop.
- "How friends join" on a server's page lists this PC's LAN/VPN addresses with the port. There's an
  on-click lookup of the internet address (api.ipify.org, added to the privacy policy with SteamCMD,
  which it was missing), a port-forwarding hint, and the crossplay join code from the log. Two
  adapters on one subnet (the owner's eno1 and a USB NIC) both show, labelled by adapter.
- PR #3 (local servers) merged. Item 2 started: hosted servers over FTP/FTPS/SFTP
  ([[0021-launchheim-hosted-servers-through-their-files]]):
  - FluentFTP 55.1.0, SSH.NET 2026.0.0 and Bouncy Castle 2.7.0 added, with their notices and licenses.
  - The log follower now reads from an `ILogSource`.
  - The plugin writes a `status.json` heartbeat, because hosted private servers can't be seen otherwise.
  - Checked end to end against podman SFTP and FTP containers: 2.1 GB server upload, the server run
    from the container's folder, then status, commands, log and stop through the files.
- The owner's Test connection on a hosted server without a user name crashed LaunchHeim (SSH.NET's
  `ArgumentException` in `NoneAuthenticationMethod`). Now:
  - Settings are validated per field, and the server page outlines what's missing, with a message
    under the box: on Save, Test connection, Upload and Start, and live while typing after that.
  - Test connection saves the form first.
  - Library errors become `IOException`s.
  - Every QML-started server action, the console's command, Update's Install now, the Play page's
    status refresh and installing from Browse go through `AppViewModel.Guard`.
- PR #4 merged. Item 4, backups, built ([[0022-launchheim-server-backups]]). Found that Proton has had an
  official Drive CLI since June 2026, and its commands came from its source on GitHub. Checked against
  the real server:
  - five CLI backups in a row with confirmed saves after the plugin fix (Valheim's `save` NRE);
  - rclone 1.76 against a local remote, with retention to 3 in both places;
  - a restore that took the world from save 12 back to save 9, which Valheim then loaded;
  - a refused restore while running;
  - an SFTP-hosted backup that found `saves` by itself.
