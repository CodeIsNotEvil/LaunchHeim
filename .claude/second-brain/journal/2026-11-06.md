# 2026-11-06

- LaunchHeim moved out of MyMonoRepo into CodeIsNotEvil/LaunchHeim ([[0018-launchheim-own-repository]]).
  The history came along through `git filter-branch` (git-filter-repo wasn't installed): an index
  filter kept `Applications/LaunchHeim/` (moved to the root), the LaunchHeim and site workflows,
  `site/`, three scripts, the Kode Mono font and the LaunchHeim notes; a message filter dropped the AI
  trailers; `--prune-empty` dropped the 45 commits that only touched other things. 195 commits, the
  app's tree identical to MyMonoRepo's `Applications/LaunchHeim` at `b4130ee`.
- The site became LaunchHeim's own (front page, download page without the app picker, privacy policy)
  and deploys to https://codeisnotevil.github.io/LaunchHeim/. The update reminder, user agents,
  package metadata and the Windows setup point at the new repository and site.
- Gotcha: `defaults.run.working-directory` was the only reason the workflows knew where the app was;
  with the app at the root the whole `defaults` block goes, not just the line.
- Open: the bridge release in MyMonoRepo for copies up to 0.7.1, the Actions secrets, the Store
  listing's URLs ([[launchheim]], "Open").
- 0.7.2 prepared as the bridge release: the first from this repository, to be published in MyMonoRepo
  too. It also fixes file dialogs with the system Qt ([[launchheim]], Gotchas): the owner's Arch
  install did nothing on "Install from file". Confirmed with a probe against qt5-base 5.15.19+kde and
  in the running app (`libqxdgdesktopportal.so` mapped; a theme the user set still wins).
- Server manager, first PR (`server-manager-base`): local dedicated servers with a Servers page, mods
  from a linked instance, the server plugin (RCON plus file channel) and the console's Server tab.
  The owner chose the order (base and local, then a generic FTP host, then G-Portal, then backups)
  and LaunchHeim's own plugin ([[0019-launchheim-server-manager]],
  [[0020-launchheim-server-plugin-speaks-source-rcon]], roadmap and backup plan in
  [[server-manager]]). Mods come from a linked instance instead of a mod list per server; that's a
  change from the plan.
- Valheim's server rules come from the game itself, read with ilspycmd (`FejdStartup`, `ZNet`,
  `Terminal`, `MessageHud`). Gotchas in [[launchheim]]: the password is checked against the world name
  and not the server name, a missing `-public` means public, QML reserves `public`, and CHANGELOG can't
  have an "Unreleased" section.
